1. PREPARAR EL COMPUTADOR
Instalar Node.js/npm, PostgreSQL 18 y, si probarán IA, Python compatible con los
requirements. Versiones declaradas como comprobadas en el proyecto de origen:
Node 24.15.0 / npm 11.12.1, Python 3.13.14 y PostgreSQL 18.1. No se requiere Git.
Mobile usa Expo SDK 57: el cliente Expo Go o build de desarrollo del teléfono
DEBE ser compatible. Exportar JavaScript no equivale a instalar una app nativa.
Comprobar en PowerShell: node --version; npm.cmd --version; python --version.
Conservar la contraseña del PostgreSQL que instalen en SU equipo, en privado.
No es la misma contraseña de las cuentas PMP/Firebase.

2. DESCOMPRIMIR
Extraer TODO el ZIP, por ejemplo en C:\PMP\PMP_Suite_V2.0_Pruebas.
No trabajar dentro del ZIP ni separar shared de Web y Mobile.
Abrir PowerShell en la carpeta que contiene este archivo y herramientas.
Si Windows bloquea los scripts descargados, revisar primero su contenido y
seguir la política local del equipo. No es necesario desactivar controles ni
cambiar la política global. Los comandos manuales están también en la guía.

3. INSTALAR DEPENDENCIAS
  .\herramientas\Instalar_Dependencias.ps1 -IncluirIA
Omitir -IncluirIA solo si no probarán análisis IA. Se utiliza npm ci con los
lockfiles, sin actualizar versiones ni ejecutar hooks de instalación. Si falta
un binario nativo, revisar el error concreto antes de autorizar su instalación.
No instala Node/PostgreSQL/Python, no crea datos y no arranca procesos.
La suite Mobile importa pruebas Web: instalar también dependencias de Web.

4. RESTAURAR LA COPIA DE DATOS
Con PostgreSQL 18 funcionando en TU computador, ejecutar UNO de estos ejemplos:
Matías:
  .\herramientas\Restaurar_Base_Pruebas.ps1 -Base pmp_suite_pruebas_matias
Luis:
  .\herramientas\Restaurar_Base_Pruebas.ps1 -Base pmp_suite_pruebas_luis
La contraseña PostgreSQL se solicita sin mostrarla. El script verifica SHA256,
acepta solo servidor local y nombres pmp_suite_pruebas_*, y rechaza destinos que
ya existan. No elimina bases, no ejecuta DROP, no sobrescribe y no migra la BD
habitual. La restauración se ejecuta en una sola transacción.
Si PostgreSQL usa otra ruta, usuario o puerto, indicar -PostgresBin, -Usuario o
-Puerto. No cambiar el puerto del servicio habitual para acomodar el paquete.
El archivo .dump ya incluye esquema y datos. schema_actual.sql es referencia;
NO aplicarlo después del dump ni ejecutar migraciones históricas o seeds.
Si algo falla, conservar el mensaje sin secretos. No reintentar sobre la misma
base ni borrarla automáticamente; revisar con Rafael.

5. CREAR LAS PLANTILLAS DE CONFIGURACIÓN
  .\herramientas\Configurar_Plantillas.ps1
Crea .env desde .env.example solo cuando no existe. No configura secretos.
Editar en privado:
  03_Backend/pmp-api/.env
    DATABASE_URL: usuario/contraseña de TU PostgreSQL y base creada en el paso 4.
    Si la contraseña tiene caracteres reservados de URL, codificar ese componente.
    FIREBASE_SERVICE_ACCOUNT_PATH: ruta a la credencial autorizada, externa al ZIP.
    PORT: 4000 si está libre.
  04_Frontend/.env
    VITE_CORE_URL y VITE_API_URL: http://localhost:4000 (sin /api).
    Los campos VITE_FB_* son configuración pública cliente tomada de Mobile;
    no constituyen una clave privada ni sustituyen la credencial Admin.
  07_Mobile/.env
    EXPO_PUBLIC_API_URL: http://IP_LAN_DE_TU_PC:4000/api.
    En emulador Android estándar puede ser http://10.0.2.2:4000/api.
Usar una terminal nueva sin variables de otro proyecto. No copiar el .env de
Rafael ni su IP LAN. Web, Mobile y Admin deben corresponder al mismo Firebase.
Si se acuerda un Firebase separado, hay que configurar los tres componentes y
vincular los UID correctos: la copia de usuarios actual no hace ese trabajo.

6. INICIAR EN TERMINALES SEPARADAS
Siempre desde la raíz del paquete:
  .\herramientas\Iniciar.ps1 -Modulo Backend
  .\herramientas\Iniciar.ps1 -Modulo Web
  .\herramientas\Iniciar.ps1 -Modulo Mobile
El asistente Backend rechaza conexiones fuera de PostgreSQL local o cuyo nombre
no comience por pmp_suite_pruebas_. Es una comprobación del asistente, no una
modificación del código ni una barrera si se decide ejecutar node manualmente.
Comprobar la configuración antes de usar comandos manuales de la guía.
Los scripts no detienen servicios ni buscan otros puertos automáticamente.
Web: http://localhost:5173
API: http://localhost:4000/api/health
Swagger: http://localhost:4000/docs
Metro: normalmente 8081. Seguir la dirección indicada por Expo.
Una respuesta /health confirma el proceso; no verifica por sí sola BD o login.
Para cerrar un proceso iniciado aquí, Ctrl+C en su propia terminal.

7. TELÉFONO
PC y teléfono deben tener conectividad entre sí. No usar localhost en el teléfono.
Revisar IP LAN, API encendida y cliente Expo compatible. No abrir el firewall ni
cambiar la red sin coordinarlo. Si cambia .env, reiniciar solo el Metro de este
paquete, desde su terminal. El engranaje azul de Expo Go no pertenece a PMP.
El aviso de persistencia Auth en memoria y el ajuste de Safe Area siguen siendo
pendientes conocidos del código de origen; el empaquetado no los corrige.

9. PRUEBAS AUTOMATIZADAS Y COMPILACIÓN
No es necesario ejecutarlas para abrir la aplicación. Usar una terminal dedicada.
En Backend, las suites declaradas usan mocks. Para reforzar el aislamiento:
  $env:DATABASE_URL='postgresql://isolated:isolated@127.0.0.1:1/isolated'
  $env:FIREBASE_AUTH_EMULATOR_HOST='127.0.0.1:1'
  cd 03_Backend/pmp-api
  npm.cmd test
Cerrar esa terminal después de la prueba; no utilizar esas variables al arrancar.
En otra terminal, desde 04_Frontend:
  npm.cmd test
  npm.cmd run build
En otra terminal, desde 07_Mobile:
  npm.cmd test
  $env:EXPO_NO_DOTENV='1'
  $env:EXPO_OFFLINE='1'
  $env:EXPO_PUBLIC_API_URL='http://127.0.0.1:1/api'
  .\node_modules\.bin\expo.cmd export --platform ios --platform android
Estas exportaciones son bundles; no prueban cámara, teclado, Safe Area ni un
binario instalado. No ejecutar verification/*.mjs ni *.browser.mjs como un
arranque general: tienen precondiciones, fixtures y destinos propios.
No ejecutar ciclos, carga de stock ni scripts de corrección de datos automática.
